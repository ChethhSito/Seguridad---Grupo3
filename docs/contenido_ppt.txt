CONTENIDO PARA PPT — SEMGREP (ENFOQUE GENERAL)
Cuatro diapositivas de contenido. Este texto describe el producto, no un repositorio de práctica.

DIAPOSITIVA 1. ARQUITECTURA DE SEMGREP Y SINTAXIS DE REGLAS
• Semgrep es una herramienta SAST: analiza código fuente sin ejecutar la aplicación.
• Recibe archivos de código y reglas YAML. Analiza la estructura de ambos, compara patrones y produce hallazgos con regla, ubicación y severidad.
• Las reglas pueden buscar patrones estructurales o seguir el flujo de datos desde una fuente hasta una operación sensible (análisis de taint).
• Una regla típica define id, languages, severity, message y pattern. Las metavariables, como $X, hacen que un patrón coincida con diferentes expresiones.
Idea para explicar: el AST genérico permite comparar la forma del código; Semgrep no depende solo de buscar texto literal.

DIAPOSITIVA 2. SEMGREP MULTIMODAL: SAST + IA
• Semgrep Multimodal combina hallazgos basados en reglas con razonamiento de IA para detección, triaje y orientación de corrección.
• El motor determinista identifica patrones y aporta contexto técnico; la IA evalúa información adicional para priorizar casos y reducir avisos irrelevantes.
• Esta capacidad pertenece a la plataforma Semgrep. La edición comunitaria permite escanear con reglas, pero no implica por sí sola que Multimodal esté activo.
Idea para explicar: SAST señala un posible problema; el análisis con IA ayuda a decidir cuáles hallazgos merecen atención primero.

DIAPOSITIVA 3. COBERTURA Y CATÁLOGO DE REGLAS
• Semgrep Community Edition anuncia más de 3 000 reglas comunitarias personalizables.
• La comparación oficial de productos anuncia más de 900 reglas Pro de alta confianza para la plataforma comercial.
• Hay reglas para clases de fallas como inyección, XSS, SSRF y errores de configuración; también se pueden crear reglas específicas de una organización.
• La cifra “20 000+ reglas propietarias” aparece en la consigna del curso, pero no tiene respaldo en las fuentes oficiales actuales consultadas. Evitar presentarla como cifra comprobada.
Idea para explicar: reglas publicadas, reglas seleccionadas para un lenguaje y hallazgos detectados son cantidades distintas.

DIAPOSITIVA 4. INTEGRACIÓN EN CI/CD Y FLUJO DE DESARROLLO
• Semgrep puede ejecutarse localmente y en pipelines como GitHub Actions, GitLab CI/CD o CircleCI.
• En una solicitud de cambios, el pipeline puede analizar el código, publicar resultados y ayudar a revisar problemas antes de integrar la modificación.
• El flujo recomendado es escanear, revisar los hallazgos, corregir el código y volver a escanear; la plataforma puede ofrecer análisis de cambios y comentarios en PR/MR.
• Un hook local pre-commit y un workflow de CI son mecanismos diferentes: el primero corre antes del commit y el segundo en la plataforma de integración.
Idea para explicar: integrar el análisis en el desarrollo permite detectar problemas antes de que lleguen a producción.
